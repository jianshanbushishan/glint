以下为历史版本验收记录，不代表当前 JSON 配置和日志级别设置已完成桌面交互验收。

- `cargo clippy --workspace --all-targets -- -D warnings`：通过。
- `cargo build --workspace --release --locked`：两个发布可执行程序构建成功。
- IPC 在真实 Windows 命名管道上往返，验证重复实例独占、消息长度限制，以及跨进程大于管道缓冲区的配置传输。
- 独立 `glint --no-hooks` 子进程完成默认配置加载、配置校验、错误保存回滚、偏好保存、动作新增删除、暂停恢复、外部文件错误重载及恢复、正常退出。
- 识别测试涵盖默认模板、自身匹配、方向区分、平移缩放、不同采样和抖动、无效输入。

- 使用独立 `.glint/qa-native` 配置完成实际交互：GUI 暂停控制、错误提示和磁盘回滚、有效配置重新应用、偏好保存到 JSON。
- 在本机 200% 缩放下，原生左键拖动完成手势重新录制并写入 `gestures.json`；录制保持暂停状态，未执行绑定动作。
- 恢复后，向右拖动识别结果为 `right · 100%`，执行 `Ctrl+A`，设置程序编辑器文本实际被全选，后台记录动作完成且无错误。
- 开启手势时，触发键短按仍可正常点击侧栏；关闭设置窗口后，后台仍可通过 IPC 查询，随后正常退出。

## 本次交互发现并修复

- 后台只有线程级 DPI 设置，在本机 200% 缩放下，钩子坐标与窗口查询 API 的坐标不一致，无法取得手势起点窗口。现在启动原生后台时设置进程级 Per-Monitor V2 DPI 感知，并使用物理坐标拾取窗口；同一录制与动作执行流程复测通过。
- 释放事件原先没有把松开位置纳入轨迹。现在即使没有中间移动事件，也会根据最终位置判断位移并保留终点；增加了对应回归测试。

坐标处理依据：[鼠标钩子坐标定义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-msllhookstruct)、[物理坐标窗口拾取](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-windowfromphysicalpoint)。

## 图标、紧凑布局及主题更新

- 图标第二版采用薄荷绿珐琅轨迹、平滑高光和深绿色缎面底板；已重新生成九种尺寸的 ICO。
- 直接解析两个 Release EXE 的 PE 资源，均包含图标组 ID 1 及九个图层。GPUI 窗口和后台托盘使用同一资源。
- 紧凑版浅色手势页及窗口/侧栏图标已通过桌面截图检查。
- 外观配置支持 `system`、`light`、`dark`，默认跟随系统；GPUI 原生 Windows appearance 通知驱动自动切换，标题栏同步设置。
- 外观持久化及读写错误已有独立测试。手动浅深切换、重启保留和 Windows 实际主题切换的桌面验收，在用户按 Esc 停止后未继续，因此尚未标记为通过。
- 新增暂停托盘图标及悬停状态文本：隔离原生后台连续两轮暂停/恢复，`Shell_NotifyIconW(NIM_MODIFY)` 均成功且后台无错误；资源选择回归测试通过。暂停图标为独立资源 ID 2，保留原有程序图标 ID 1。

## 轨迹显示排查

- 用户确认重启后台后手势动作恢复，但轨迹不可见；原始失去识别的原因尚未确定。
- 鼠标采样、位图非透明像素和窗口提交均已实机记录。透明位图渲染使用 `UpdateLayeredWindow`，独立线程按帧刷新。
- Debug / Release 原生测试窗口截图可见绿色线条；真实轨迹窗口置前后截图同样可见。现版本显式建立 TOPMOST 窗口，先显示再设置层级，绘制期间维护层级且不主动激活窗口。
- 平台 6 项常规测试和 Clippy 通过。`cargo test -p glint-platform native_trail_submission -- --ignored --nocapture` 可单独运行原生提交检查；此测试会短暂显示轨迹窗口。
- 最后一次置顶修正后，用户实机确认右键拖动轨迹已可见。手势识别和轨迹显示均已恢复。临时保留轨迹模式已移除，当前后台未开启诊断输出。
- 后续修正新手势开始时旧位图闪回：Begin/Clear 立即隐藏窗口并清除已提交帧的 epoch；只有当前手势成功提交位图后，周期置顶才允许显示窗口。平台测试、Clippy 和 Release 构建通过，连续手势的视觉效果待用户验证。

## 已知边界

### 设置界面精简验证

- 手势卡片仅显示预览和名称，点击选择后展开录制表单；新建入口保持独立。
- 动作表单按需展开，启动参数仅在 launch 类型下显示；填写帮助、配置维护、高级工具分别保存独立的展开状态。
- 概览合并统计信息并折叠事件日志；触发键改为中文按钮，保存仍沿用原有配置校验。
- Release 构建、设置程序 Clippy、2 项外观测试及 GPUI 启动自检通过；本轮未进行桌面点击和截图验收。

- 首版只实现 Windows 平台；没有安装器、自动更新或开机启动设置。
- 当前原生动作在专用线程串行执行，暂停/重载会丢弃待执行的旧动作；已经进入的原生调用不能强行中断。
- GUI 按动作 ID 保存增量覆盖，修改同 ID 的 JSON 基础动作时，界面覆盖仍然优先。
- 依赖构建会报告 `proc-macro-error2 2.0.1` 的未来 Rust 兼容提示，目前所用工具链构建通过。
